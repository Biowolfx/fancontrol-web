# Plan: Agent Telemetry — Full Sensor & DSM Scheme Sync

## Problem

When agent connects to server:
- Server shows "No telemetry" / empty fan list
- DSM scheme editor on server reads LOCAL scemd.xml, not agent's
- No mechanism to push config/scheme changes from server to agent

## Current Flow

1. Agent → `agent:connect` with `{fans, temp_sensors, hdd_sensors}` (config only, no RPM/values)
2. Agent → `agent:telemetry` every 5s with `{fans: {rpm, pwm_value}, temp_sensors: {value}, hdd_sensors: {temp}}`
3. Server stores in `state['nodes'][node_id]['telemetry']` + SQLite
4. Browser receives `node:telemetry` → `nodesData` → `renderRemoteNodeTree`
5. DSM scheme editor calls `/api/dsm/schemes` → reads LOCAL `/usr/syno/etc.defaults/scemd.xml`

## What's Missing

- `control_method` (hwmon/dsm_scemd) per fan not sent
- DSM schemes not sent at all
- No way to apply scheme changes to remote agent
- `renderRemoteNodeTree` shows fans from telemetry but no control_method info

## Plan

### 1. Agent sends richer data on connect

**File: `agent/client.py`**

`_get_local_config()` → add `kernel_info` and `dsm_schemes`:

```python
def _get_local_config():
    with state_lock:
        config = {
            'fans': {k: {kk: vv for kk, vv in v.items()
                         if kk not in ('rpm', 'pwm_value')}
                     for k, v in state['fans'].items()},
            'temp_sensors': state['temp_sensors'],
            'hdd_sensors': state['hdd_sensors'],
            'kernel_info': state.get('kernel_info', {}),
        }
        # Add DSM schemes if available
        from core.dsm_fan import is_dsm_fan_available, get_all_schemes
        if is_dsm_fan_available():
            config['dsm_schemes'] = get_all_schemes()
        return config
```

### 2. Agent sends control_method in telemetry

**File: `agent/client.py`**

`_get_telemetry()` → add `control_method` per fan:

```python
def _get_telemetry():
    with state_lock:

                         'label': v.get('label', k)}
                     for k, v in state['fans'].items()},
            'temp_sensors': ...,
            'hdd_sensors': ...,
        }
```

### 3. Server stores DSM schemes and kernel_info in node state

**File: `server/agent_handlers.py`**

In `handle_agent_connect()`, store `dsm_schemes` and `kernel_info` from agent config:

```python
with state_lock:
    state['nodes'][node_id] = {
        ...
        'dsm_schemes': agent_config.get('dsm_schemes', []),
        'kernel_info': agent_config.get('kernel_info', {}),
    }
```

### 4. Browser renders DSM scheme editor for remote nodes

**File: `templates/js/main.js`**

When clicking a DSM fan on a remote node → open DSM scheme editor but fetch schemes from `nodesData[nodeId].dsm_schemes` instead of `/api/dsm/schemes`.

Modify `renderDsmSchemeEditor()` to accept optional nodeId parameter:
- If `nodeId` provided → use `nodesData[nodeId].dsm_schemes` (remote)
- If no nodeId → fetch from `/api/dsm/schemes` (local)

Modify `selectNodeFan()` to pass nodeId when clicking DSM fan on remote node.

### 5. Server proxies DSM scheme apply to remote agent

**File: `templates/js/main.js`**

When user clicks "Apply" on a remote node's DSM scheme:
- Send WebSocket event `server:dsm:apply` with `{node_id, scheme_type, entries}`
- Agent receives → applies to local scemd.xml

**File: `agent/client.py`**

Add handler for `server:dsm:apply`:
```python
@sio.on('server:dsm:apply')
def _on_dsm_apply(data):
    from core.dsm_fan import update_scheme_entry
    scheme_type = data['scheme_type']
    for entry in data.get('entries', []):
        update_scheme_entry(scheme_type, entry['index'], entry)
```

**File: `server/agent_handlers.py`**

Add endpoint or Socket.IO emit for pushing scheme changes to agent.

### 6. Server exposes DSM schemes via API for remote nodes

**File: `server/routes.py`**

Add `GET /api/nodes/<node_id>/dsm/schemes` — returns schemes from node state.
